## Исправления перед сдачей

1. API отклоняет слишком длинные и выходящие за signed int64 идентификаторы с HTTP 422; добавлены regression-проверки.
2. Платные AI-вызовы ограничены скользящей минутой и числом одновременных запросов. При отказе остаются серверные факты; слот освобождается даже при ошибке адаптера.
3. Production-кнопки лендинга ведут к реальному подготовленному датасету и не обещают отключённый synthetic demo.
4. Smoke-скрипт поддерживает `--require-live-ai`, чтобы резервный ответ не считался успешной проверкой OpenAI.
5. Обновлены основной и frontend README, шаблон переменных, совместимые Railway-конфиги и подробная инструкция нового деплоя через Dashboard.

## Что ещё проверяется после публикации

Railway-сервисы и публичные домены в ходе этого прогона **не создавались**. Сборка Linux-контейнеров Railway, квоты аккаунта, GitHub-доступ, публичные TLS-домены и CORS должны быть проверены после выполнения [RAILWAY.md](RAILWAY.md). Локальный успех не заменяет эту проверку.

Для проверки опубликованной версии запустите из `backend` своим Python:

```bash
python scripts/smoke_api.py --base-url https://<backend-domain> --origin https://<frontend-domain> --require-live-ai
```

Если AI намеренно выключен, уберите `--require-live-ai`: обязательные графовые функции и CSV работают без него. Ограничения MVP, включая отсутствие browser upload, авторизации и необязательных временных/ML-методов, перечислены в [README](../README.md).
